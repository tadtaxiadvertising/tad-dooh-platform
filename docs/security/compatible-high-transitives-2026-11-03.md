# Security-compatible transitive fixes — 2026-11-03

## Evidence and rationale
On `main@148af7ce7f11c89bafcb14a8d2cce173ea29f423`, `pnpm audit --audit-level=high` reports **64 findings: 18 high, 38 moderate, 8 low**. This is a vulnerability/installation count, not proof of 18 unique exploitable paths. Issue #195 tracks the whole backlog.

This PR updates only exact, known affected *installed versions* while staying within the same package major. Examples: body-parser compressed-body DoS (1.20.x and 2.3.x), Next PostCSS source map disclosure (8.4.31), Swagger js-yaml 4.1.0, NestJS CLI glob/picomatch and lodash used by NestJS config.

The version-scoped selectors avoid forcing a new major on all parents. The lockfile MUST be generated by `pnpm install --lockfile-only --ignore-scripts` rather than edited manually. Temporary workflow permission `contents:write` is restricted to this branch, and the workflow MUST be removed before any merge. A readonly acceptance gate confirms the resulting lock and installed dependencies.

## Verification matrix
- Frozen lockfile install + security regression test.
- `pnpm audit --audit-level=critical` and capture the full high audit count. The existing high severity audit gate is **never relaxed**.
- TypeScript across all workspaces, API unit tests, local browser checks, four Docker builds, and driver offline semantics.
- No direct SMTP, Zod 3 to 4, tmp 0.x or serialize-javascript major upgrade in this PR. Those require independent compatibility review.

## Risks and rollback
A dependency override can affect transpilation, request body parsing or CLI operations even within a major. Validate the integrated application and remove/revert the PR if verification fails. Never deploy from a draft or with unaccepted high vulnerabilities. No database changes or production secrets involved.
