# Payment evidence review version contract (#623)

The admin-only review endpoint requires the exact `submittedAt` value returned by the pending evidence or evidence detail endpoint. Send it unchanged as `expectedSubmittedAt` (UTC ISO-8601 with three millisecond digits). A missing or invalid value returns HTTP 400. A different stored version returns HTTP 409 with code PAYMENT_EVIDENCE_VERSION_CONFLICT, including when a newer version is already terminal. The transaction still uses compare-and-set and checks the winner's version. Do not silently retry a stale decision.

Client rollout: fetch the current evidence detail, display its receipt and version, preserve that version through the operator decision, send a fresh Idempotency-Key for each new logical decision. On 409 reload and require explicit human review of the replacement before issuing a new decision/key; on unknown outcome reconcile, not blind retry. The old key remains associated with its original body under the existing idempotency contract. Never synthesize a version from client time or fetch the latest version just to approve an old displayed receipt.

This intentionally tightens the HTTP contract. Repository search did not locate a direct portal caller; external clients must be inventoried and updated before rollout. Production release remains blocked by #217/#627. No migration, database writes or portal implementation in this PR. A generic HumanReviewTask snapshot may still contain an old URL after resubmission; consumers must use the current PaymentEvidence detail until the snapshot is corrected. This is not a proof that a particular file's bytes are immutable.
